Motivation

The Question

You have a pretrained encoder.

You have a task with limited labeled data.

How much of the model should you train?

What Decides?

  • Representation: what does the pretrained encoder already contain?
  • Task: what does the downstream task require (vector, spatial features, similarity)?
  • Data: what can the target data support (labels, domain shift)?

A larger training set helps, but it is not the only deciding factor.

Adaptation Strategies

Five Strategies

Options to compare, not a fixed ranking: start with frozen features.

At a Glance

Strategy What is learned? Key property
k-NN Nothing; uses labeled reference images Fast test of feature quality
Linear probe A small prediction head Frozen encoder; features can be cached
Partial fine-tuning Selected encoder layers + head Encoder becomes task-specific
Full fine-tuning Entire encoder + head Maximum flexibility; higher training cost
LoRA Low-rank updates to selected weights + head Few trainable parameters, but backprop still passes through the encoder

The Strategies

k-NN — No Gradient-Based Training

  • Embed labeled reference images with a frozen encoder
  • For a new image, retrieve the \(k\) closest reference embeddings
  • Predict from their labels (majority or similarity-weighted vote)
  • Hyperparameters: \(k\), distance metric, weighting rule

What it tells you: whether the pretrained representation already separates your target data.

Linear Probe — Freeze Encoder, Train Head

  • Keep the pretrained encoder frozen
  • Train only a linear classifier on the embeddings: \(\text{Linear}(d, K)\)
  • Embeddings can be cached: the encoder does not run every epoch

Good performance: the labels are linearly accessible from the representation.

A poor result does not prove the features are useless: the information may be nonlinear, or the feature extraction unsuitable.

Partial Fine-Tuning

  • Freeze most of the backbone
  • Unfreeze selected blocks (e.g. the last two) and the task head
  • The representation can change, with fewer trainable parameters

Which layers to tune depends on architecture, pretraining objective and task: an experimental choice.

Full Fine-Tuning

  • Update the encoder and the new head jointly
  • Most flexible strategy
  • More training memory, higher risk of overfitting or losing pretrained behavior
  • Use a smaller learning rate for the encoder than for the head

Not inherently a last resort: fine-tuning a small model can work with modest data. Measure on held-out data.

LoRA — Low-Rank Updates

\[ W' = W + \frac{\alpha}{r}BA, \qquad B \in \mathbb{R}^{d_{out}\times r},\quad A \in \mathbb{R}^{r\times d_{in}} \]

  • \(W\) stays frozen; only \(A\), \(B\) and the head are trained
  • \(r(d_{in}+d_{out})\) instead of \(d_{out}d_{in}\) parameters; rank \(r\) controls capacity
  • Unlike adapters, LoRA inserts no new layer: it changes existing weights
  • Backprop still passes through the whole encoder

Choosing an Adaptation Strategy

What Limits Your Baseline?

Question What to try or check
Are the features already useful? Compare k-NN and linear probe
Is the encoder right for this domain? Compare general, vision-language and domain-specific encoders
Does the task need spatial predictions? Patch / feature-map outputs and a decoder or detection head
Does the probe underfit? More capable head, partial FT, LoRA or full FT
Is the model overfitting? Validation design, regularization, augmentation, less capacity
Is training expensive? Cache frozen features, smaller backbone, parameter-efficient methods
Is inference expensive? Backbone, input size, precision; freezing alone does not help

Establish a reliable baseline, then investigate what limits it.

Three Questions Before Fine-Tuning

  1. Are the pretrained features already useful for the target task?
  2. Does the task require an image-level vector, spatial features, or a similarity embedding?
  3. Does updating the encoder improve held-out performance enough to justify the cost?

There is no universal dataset-size threshold that determines the best strategy.

Worked Scenarios

Scenario 1: Camera-Trap Species

Scenario

  • 500 labeled camera-trap images
  • Task: species classification

Recommended start: global embeddings + k-NN or linear probe, with a split that separates cameras or sites.

Compare fine-tuning if the baseline is insufficient. In the lecture’s experiment on unseen sites, frozen features reach 0.57 macro-F1, adapted backbones 0.85–0.87.

Scenario 2: Medical Domain Shift

Scenario

  • 800 labeled chest X-rays
  • Two encoders: a general-purpose DINO model and a medical-image model

Recommended start: linear probe (optionally k-NN) on both encoders, with a patient-level split.

Evaluate AUROC and sensitivity. If both frozen baselines are inadequate, compare fine-tuning starting from the better encoder.

The number of images alone does not decide the method.

Scenario 3: Land-Cover Segmentation

Scenario

  • Satellite images with pixel-level annotations
  • Strong domain shift from ground-level photos

Recommended start: spatial features + a trainable segmentation decoder on a frozen encoder.

Then evaluate encoder fine-tuning. A global embedding loses the spatial detail this task needs.
